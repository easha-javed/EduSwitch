## Overview

Students in Pakistan rarely write in a single language. A typical message looks like this:

> *Sir meri attendance 72% hai, can I still sit in the final?*

Systems trained on clean, single language text often struggle with such input. EduSwitch is an NLP system and experimental study that takes one free form student message and returns two things:

| Output | Example for the message above |
|---|---|
| Language of every word | Sir `EN`, meri `UR`, attendance `EN`, 72% `NUM`, hai `UR`, can `EN` ... |
| Intent of the query | `exam` with a confidence score |

**Research question:** How well do multilingual Transformers understand Urdu English code switched student queries, and does targeted fine tuning improve them?

The value of the project is the experiment. We compare a classical baseline, frozen and fine tuned multilingual Transformers, and a few shot LLM reference, then measure robustness across English, Roman Urdu, Urdu script and code switched text, and analyze where the models fail.

## Features

* Word level language identification with four labels: English, Urdu (Roman Urdu or Urdu script), numbers, other
* Intent classification over ten student query categories
* Leakage safe data pipeline: exact and near duplicate detection, group aware splits, human written test set
* Seven model configurations compared on one frozen test set, with three seed averaging
* Robustness analysis by language type and by amount of code mixing
* Automatic error export for error analysis
* Streamlit demo that works with baseline models from day one and upgrades when trained models are added
* Tests and continuous integration

## How it works

```text
Student query
      |
Normalization and word tokenization
      |
      +--> Token classifier  --> EN / UR / NUM / OTHER for every word
      |
      +--> Sentence classifier --> intent and confidence
      |
Post processing (code switched flag when both English and Urdu are present)
      |
Streamlit interface
```

**Intent classes:** assignment, exam, attendance, course withdrawal, registration, fee, tech support, grades, schedule, other.

## Experiments

| ID | Model | Role |
|---|---|---|
| B0 | Majority class | Sanity floor |
| B1 | TF IDF (word and character n grams) with Logistic Regression | Classical baseline |
| B2 | mBERT, frozen encoder with linear head | Base multilingual model |
| B3 | XLM-R base, frozen encoder with linear head | Base model for the base versus fine tuned comparison |
| F1 | mBERT, fully fine tuned | Fine tuned comparison |
| F2 | XLM-R base, fully fine tuned | **Main model** |
| X1 | XLM-R with LoRA adapters | Parameter efficient variant (optional) |
| X2 | Few shot LLM through an API | Modern reference point (optional) |
| L0 | Dictionary language ID | Language ID baseline |
| L1 | XLM-R token classifier | Language ID model |

Primary metric is **macro F1** because intent classes are not perfectly balanced. We also report accuracy, precision, recall, confusion matrices and per slice scores. Fine tuned runs use three random seeds and report mean and standard deviation.

## Getting started

Requires Python 3.10 or newer.

```bash
git clone https://github.com/easha-javed/EduSwitch.git
cd eduswitch
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m pytest -q
```

Run the demo with the baseline models:

```bash
python -m src.dataset intent --input data/sample/sample_queries.csv --real-only-test
python -m src.baselines intent
streamlit run app/app.py
```

The repository ships with about 60 sample queries so everything runs immediately. These are for smoke testing only.

Training Transformers needs a GPU. Install `requirements-train.txt` and use a free Colab or Kaggle GPU for the long runs. See `notebooks/00_colab_quickstart.ipynb`.

## Reproducing the pipeline

| Step | Command |
|---|---|
| Draft synthetic queries (human review required) | `python -m src.data_generation --provider groq` |
| Build leakage safe intent splits | `python -m src.dataset intent --input data/raw/queries.csv --real-only-test` |
| Pre label tokens for annotation | `python -m src.prelabel_lid export --input data/raw/queries.csv --out data/raw/lid_to_correct.csv` |
| Import corrected tokens | `python -m src.prelabel_lid import --input corrected.csv --out data/raw/lid_annotated.json` |
| Build language ID splits | `python -m src.dataset lid --input data/raw/lid_annotated.json` |
| Classical baselines | `python -m src.baselines intent` and `python -m src.baselines lid` |
| Intent models | `python -m src.train_intent --model xlmr --mode full --run-name xlmr_finetuned` |
| Language ID model | `python -m src.train_lid --model xlmr` |
| Few shot LLM reference | `python -m src.llm_fewshot --provider groq` |
| Evaluate and export errors | `python -m src.evaluate --pred results/predictions/<run>.csv` |
| Inter annotator agreement | `python -m src.agreement a.csv b.csv --col intent` |

Seed 42 is fixed in `src/config.py`. Every number reported in the paper or slides must come from a file in `results/`.

## Data and ethics

* The final test set is written by humans, never generated by an LLM, and frozen before model tuning.
* LLM drafted queries are used for training only after human review.
* No real student names, IDs or private messages are stored. Collected messages are anonymized.
* Sources and licences are listed in [data/README.md](data/README.md). Annotation rules are in [data/annotation_guide.md](data/annotation_guide.md).

## Limitations

* The dataset is small and partly synthetic, so results describe this domain and may not transfer to other universities or settings.
* Roman Urdu has no standard spelling, which makes both annotation and modeling noisy.
* Intent labels follow our own annotation guide, and some queries have more than one valid intent.
* Language ID treats names and loanwords by convention, documented in the annotation guide.

These points are revisited with evidence in the error analysis section of the final report.
